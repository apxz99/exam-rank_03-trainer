rip ต้องทำอะไร

Subject (ต้นฉบับ)
Assignment name  : rip
Expected files   : *.c *.h
Allowed functions: puts, write
--------------------------------------------------------------------------------

Write a program that will take as argument a string containing only parenthesis.
if the parenthesis are unbalanced (for example "())")
your program shall remove the minimum number of parentheses for the expression to be balanced.
By removing we mean replacing by spaces.
You will then print all the solutions (can be more than one).

The order of the solutions is not important.

For example this should work:
$> ./rip '(()' | cat -e
 ()$
( )$
$> ./rip '((()()())())' | cat -e
((()()())())$
$> ./rip '()())()'| cat -e
()() ()$
()( )()$
( ())()$
$> ./rip '(()(()(' | cat -e
(()  ) $
( )( ) $
( ) () $
 ()( ) $
อธิบายภาษาไทย

โจทย์

รับสตริงวงเล็บทาง argument ลบวงเล็บ น้อยที่สุด ให้สมดุล (ลบ = แทนด้วยช่องว่าง) พิมพ์ทุกคำตอบ

./rip '(()'   →   " ()"  และ  "( )"

คำใบ้

  • นับจำนวนที่ต้องลบในรอบเดียว: ( → open++, ) → ถ้ามี open ก็ open-- ไม่งั้น close++ → ต้องลบ open + close ตัว
  • backtracking ทีละตำแหน่ง: ลบ (ถ้ายังมีโควตา) หรือ เก็บ
  • เก็บยอดวงเล็บเปิดค้าง (depth) ถ้าติดลบเมื่อไหร่ตัดทิ้งได้เลย
  • จบสตริงแล้วโควตาหมดและ depth = 0 → puts

ระวัง

  • ต้องแทนด้วยช่องว่าง ไม่ใช่ตัดออก
  • ห้ามมีคำตอบซ้ำ
  • สตริงที่สมดุลอยู่แล้ว → พิมพ์ตัวมันเอง

argument กับ stdin ต่างกันยังไง

โปรแกรมรับข้อมูลจากภายนอกได้หลายช่องทาง ใน Rank 03 ใช้แค่ 2 ทาง: argument กับ stdin ทั้งสองส่งข้อมูลเข้าโปรแกรมเหมือนกัน แต่ ส่งคนละช่อง และอ่านในโค้ดคนละวิธี

1. Argument (argv)

คือคำที่พิมพ์ ต่อท้ายชื่อโปรแกรม ตอนสั่งรัน shell จะตัดเป็นคำ ๆ ตามช่องว่าง แล้วส่งให้ main ตั้งแต่โปรแกรมเริ่มทำงาน

$> ./powerset 5 1 2 3 4 5
int main(int argc, char **argv)
{
    // argc    = 7          จำนวนคำทั้งหมด (นับชื่อโปรแกรมด้วย)
    // argv[0] = "./powerset"
    // argv[1] = "5"        ← เป็นสตริงเสมอ! ต้อง atoi เองถ้าอยากได้ตัวเลข
    // argv[2] = "1" ... argv[6] = "5"
    // argv[7] = NULL
}
  • ได้ข้อมูลทันที ไม่ต้องเรียกฟังก์ชันอ่าน
  • ทุกตัวเป็น สตริง — ตัวเลขต้องแปลงด้วย atoi(argv[1])
  • เช็คจำนวนด้วย argc ก่อนใช้ argv[i] เสมอ ไม่งั้นอ่านเกินขอบ (เช่น if (argc != 2) return 1;)
  • ถ้าข้อมูลมีช่องว่างหรืออักษรพิเศษของ shell อย่าง ( ) * $ ต้องครอบด้วยเครื่องหมายคำพูด — ./rip '(()' ได้ argv[1] = (() (shell ตัดเครื่องหมายคำพูดออกให้)
  • ./filter "very long pattern" → argument เดียวที่มีช่องว่าง, ./filter very long pattern → 3 argument

2. stdin (standard input)

คือ "ท่อ" ข้อมูลที่ไหลเข้าโปรแกรม ระหว่างที่มันรันอยู่ เป็น file descriptor หมายเลข 0 ข้อมูลอาจมาจาก

$> echo 'abcdefabc' | ./filter abc      # จากโปรแกรมอื่นผ่าน |
$> ./tsp < square.txt                    # จากไฟล์ผ่าน <
$> ./tsp                                 # จากคีย์บอร์ด (พิมพ์แล้วกด Ctrl+D = EOF)

โปรแกรมไม่รู้ว่าข้อมูลมาจากไหน และไม่รู้ว่ายาวเท่าไร — ต้องอ่านเองทีละส่วนจนเจอ EOF

char    buf[1024];
ssize_t r;

while ((r = read(0, buf, sizeof(buf))) > 0)   // 0 = stdin
{
    // ได้มา r ไบต์ (อาจน้อยกว่าที่ขอ!)
}
if (r < 0)       // read พัง
    ...
// r == 0 → EOF ข้อมูลหมดแล้ว
  • อ่านได้หลายวิธี: read(0, …), fgetc(stdin), fscanf(stdin, …), get_next_line(0)
  • read อาจคืน น้อยกว่า ที่ขอ แม้ข้อมูลยังไม่หมด — ห้ามคิดว่า read ครั้งเดียวได้ครบ (นี่คือสิ่งที่ test read สุ่ม จับ)
  • ข้อมูลเป็นไบต์ดิบ ไม่มี '\0' ปิดท้ายให้ — ต้องจำความยาวเอง
  • echo เติม \n ท้ายข้อความให้เสมอ ส่วน printf ไม่เติม
